Working rules

Keep four people from colliding

One branch per spec

Branch as feat/005-vendor-quote-submission. Only the owner edits that spec folder and its tasks.md checkboxes.

Migrations never clash

Each feature writes supabase/migrations/20261101000N00_*.sql, with N as its spec number, so files sort in dependency order.

Shared contracts are frozen

Tables, status values, endpoints and error codes come from docs/project-overview.md. To change one, ask Member 1 and update the overview first.

Shared files have an owner

seed.sql and src/lib/validation/ belong to Member 1, the wizard and dashboard to Member 2, src/lib/ai/ to Member 4. Others add through small PRs.

P0 before P1

At 03:30, if the request → quote → compare → accept flow is not working, Member 4 pauses AI work and helps close it.

Run each spec the same way

Set .specify/feature.json to your spec, then run /speckit-analyze and /speckit-implement. Tick tasks as they land.
